This page covers the data sources that can be connected to WisdomAI: databases and data warehouses, files and repositories, BI tools, and calendars. It outlines the connection requirements, necessary configurations, and troubleshooting tips for seamless integration.

WisdomAI works with the following data sources:

## Warehouse & Database sources

- PostgreSQL
- Microsoft SQL Server
- MySQL
- Oracle
- Databricks
- Snowflake
- Google BigQuery
- Google Cloud Spanner
- Amazon Redshift
- Amazon Athena
- Teradata
- Azure Synapse & Synapse Serverless
- ClickHouse 
- Trino 
- Dremio
- MotherDuck

<Warning>
  **Note on Syncing**: After successfully adding a connection, the initial sync may take a few minutes to complete before data is available for analysis. To follow a sync, see [Manage connections](#manage-connections).
</Warning>

## File & Repository sources

- Amazon S3
- Azure Blob Storage
- SharePoint
- GitHub 
- GitLab
- Azure DevOps

Supported file types: PDFs, DOC/DOCX files, PowerPoint files, txt files, and images.

<Note>
  CSV files and direct uploads are added to a domain rather than set up as connections. To learn how to upload them, read [Upload CSV files](/setting-up-wisdom-ai/basic-tutorial-connect-and-test#3-upload-csv-files-optional).
</Note>

## BI tools

- Tableau

### Connection requirements

This section outlines common prerequisites for connecting to data sources. Specific requirements are detailed under each data source.

- **Network Access:** Ensure WisdomAI has network access to your database or data warehouse host. This may involve configuring firewall rules or security groups.
- **Authentication Details:** You will need the correct credentials (username, password, keys, etc.) for your chosen data source.
- **SSL/TLS Configuration:** For secure connections, ensure your database/data warehouse is configured to accept SSL/TLS connections, and configure WisdomAI accordingly (e.g., `SSL Mode: Require SSL` for PostgreSQL).
- **Service Accounts (Google BigQuery):** A Google Cloud service account with appropriate BigQuery permissions is required.
  <Info>
    For PostgreSQL, Amazon Redshift, MySQL, and Oracle, you can optionally connect through an SSH tunnel to a bastion host.
  </Info>

    To set up key pair authentication for Snowflake:

    1. Generate an RSA key pair (2048-bit minimum length).
    2. Register the public key with your Snowflake user.

    Here's an example key pair connection:

    ```txt
    Account or Host: xy12345.us-east-1
    Username: wisdom_analytics
    Authentication Method: Private Key
    Private Key: paste the contents of your .p8 or .pem file
    Warehouse: ANALYTICS_WH
    Role: ANALYST_ROLE
    Database filters: BUSINESS_DATA
    ```

    Access the [Snowflake Docs](https://docs.snowflake.com/en/user-guide/key-pair-auth.html) to get more information about Key Pair Authentication.

## Access settings

BigQuery, Snowflake, Amazon Redshift, ClickHouse, Databricks, PostgreSQL, Microsoft SQL Server, Azure Synapse Serverless, Oracle, and Teradata connections have an **Access** section with two rows:

| Row | What it lets WisdomAI do |
| :-- | :-- |
| **Query history** | Monitor query performance and diagnose query and database health |
| **System catalog metadata** | Read table sizes, partitions, and statistics to plan more efficient queries |

Click **Enable** on a row. WisdomAI then:

1. Checks whether the connection already has access.
2. Shows the grant statements to run, filled in with the connection's own user.
3. Checks again after you run them.

## Advanced settings

The **Advanced** section is on the connection form. Each setting is only shown for the sources listed in the table.

| Setting | What it does | Available on |
| :-- | :-- | :-- |
| **Query timeout (s)** | Stops queries that run longer than this many seconds | PostgreSQL, Amazon Redshift, Snowflake, Google BigQuery, ClickHouse, Databricks, Oracle, and MotherDuck |
| **Max bytes scanned** | Caps how much data one query may scan | Google BigQuery and Snowflake |
| **Alternate credential sets** | Use different credentials depending on a user attribute | PostgreSQL, Amazon Redshift, MySQL, Microsoft SQL Server, Teradata, Databricks, ClickHouse, Trino, Amazon Athena, Google BigQuery, Google Cloud Spanner, Dremio, Snowflake, and MotherDuck |

### Max bytes scanned

**Max bytes scanned** is set separately for two kinds of work:

| Limit | Applies to | Default |
| :-- | :-- | :-- |
| **Jobs** | Crawls and other background work | 500 GB |
| **Interactive** | Chat, dashboards, MCP, and Slack | 5 TB |

### Alternate credential sets

Alternate credential sets let a connection use different credentials depending on a user attribute, for example region. Any field you leave empty in an alternate set is taken from the main connection.

<Info>
  For how user attributes are matched to credentials, see [User attributes](/integrations/user-management/user-attributes).
</Info>

## Manage connections

After you add a connection, you manage it from the **Connections** page in the left sidebar. This section covers what happens when you save a connection and the actions in each connection's three-dot menu.

### What happens when you save

WisdomAI checks a connection when you save it. If a check fails, the form says the connection was not saved and lists each failed check with how to fix it. Fix the listed items and save again. There is no separate **Test** button.

For GitHub and GitLab connections, WisdomAI reads from the repository to check access. If it can't, it says what's missing.

The save button depends on the source:

| Button | Sources |
| :-- | :-- |
| **Save and Sync metadata** | Warehouses, Tableau, and MCP servers |
| **Save** | File, repository, and calendar sources |

Connection names can be up to 255 characters, or 30 characters for MCP servers.

### The connection menu

On the **Connections** list, click the three-dot menu on a connection to use these actions:

| Action | What it does |
| :-- | :-- |
| **Sync now** | Re-reads the connection's metadata right away |
| **Run Logs** | Shows sync history |
| **Alerts** | Notifies people when a sync fails |
| **Remove Connection** | Deletes the connection |

#### Run Logs

**Run Logs** lists each sync of the connection. For each sync, it shows how many databases and tables the sync found, or that it found none.

## How WisdomAI queries your warehouse

This section explains how WisdomAI cancels and reuses queries, and how to recognize its queries in your warehouse's own query history.

### Query cancellation

Stopping a chat answer or leaving a dashboard cancels the query running in your warehouse. Where cancellation is supported, canceled queries show up in the warehouse's own query history.

Cancellation depends on the warehouse, so it isn't available for every connection type. On ClickHouse, the connection's user also needs `SELECT` on `system.processes`. See the ClickHouse tab above.

### Result reuse

On BigQuery, Snowflake, ClickHouse, and Databricks, WisdomAI reuses an earlier result instead of running the same query again when both of these are true:

- The same query runs again for the same person within 24 hours.
- The warehouse reports that none of the query's tables changed.

This covers dashboard refreshes, chat, agents, and the Playground.

Result reuse doesn't apply to:

- Connections that use each person's own credentials.
- SQL that uses volatile functions, such as the current date or time.

<Note>
  Table previews on a domain's **Data Sources** tab can come from a cache up to 7 days old.
</Note>

### Recognize WisdomAI's queries

Every query WisdomAI runs starts with this comment:

```sql
/*{"app":"wisdom"}*/
```

Some warehouses also record an application name or user agent:

| Warehouse | What it sees |
| :-- | :-- |
| Snowflake | Application name `WisdomAI_SQLAgent` |
| Databricks | Application name `WisdomAI_SQLAgent` |
| PostgreSQL | Application name `WisdomAI_SQLAgent` |
| MotherDuck | User agent `WisdomAI_SQLAgent/1.0` |

Use these when auditing your warehouse's query history or attributing warehouse cost to WisdomAI.

## Limits

This section details any known limitations or restrictions when connecting to data sources.

- **File Size:** The Maximum file size for direct upload is 100MB. For larger files or datasets, consider uploading them to a data warehouse or cloud storage (e.g., Amazon S3) and connecting WisdomAI to the warehouse/storage.
- **Query Limits:** Be aware of any rate limits or query concurrency limits imposed by your database or data warehouse provider. WisdomAI's queries will contribute to these limits.
- **Data Type Support:** While WisdomAI strives to support a wide range of data types, some highly specialized or proprietary data types might require specific handling or may not be fully supported. Contact us if you request any assistance.

## Troubleshooting

Understand common problems and systematic troubleshooting techniques that can help you quickly identify and resolve connectivity issues.

### Common connection issues

| **Issue** | **Possible Causes** | **Resolution** |
| --- | --- | --- |
| Connection Timeout | - Network latency  <br /> - Firewall blocking  <br /> - Server overload | - Check network connectivity  <br /> - Verify firewall rules |
| Authentication Failed | - Incorrect credentials  <br /> - Expired API keys/tokens  <br /> - Account lockout | - Verify username/password  <br /> - Regenerate API keys  <br /> - Check account status |
