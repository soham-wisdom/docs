## Shared Architecture

Regardless of the model you choose, WisdomAI provides:

- **Single-tenant infrastructure**: Every customer's data is isolated within its own environment.
- **Managed operations**: WisdomAI remains responsible for upgrades, patching, and monitoring.
- **Feature parity**: The product and its features (Agents and Deep Analysis) are identical across all models.

## WisdomAI Hosted (SaaS)

In this model, WisdomAI hosts your instance within our own secure tenant. Enjoy a true SaaS experience with zero infrastructure responsibility, making it perfect for teams seeking immediate value without the burden of administrative overhead.

The advantages of choosing this model are:

- **Zero infrastructure management**: WisdomAI handles all upgrades, patching, and monitoring.
- **Fastest time-to-value**: Skip cloud provisioning and start using the product immediately.
- **Simplified billing**: A licensing model where WisdomAI covers all underlying infrastructure costs.
- **Global reach**: Access the platform across multiple geographic regions.

## Customer Hosted (Cloud-Prem)

In the Cloud-Prem model, your WisdomAI tenant is deployed **as a managed service** in isolation within your own cloud environment. This option is ideal for organizations with strict data residency mandates or existing cloud spend commitments.

<Note>
  **Important:** This is **not** a traditional self-hosted model. It operates under a hosted SaaS model, where WisdomAI retains minimal access to operate, patch, and update the service remotely, ensuring your version is always up to date.
</Note>

The advantages of choosing Cloud-Prem as your deployment option are:

- **Strict data residency**: Data never leaves your organizational boundaries or your chosen cloud account.
- **Cloud spend utilization**: Use your existing **AWS, GCP, or Azure spend commitments** to offset hosting costs.
- **Full operational visibility**: Maintain access to all raw logs for compliance and security auditing.

### Supported Environments

We support deployment across all major cloud providers:

- **On AWS**: Deployed inside your VPC; compatible with **Service Control Policies (SCPs)**.
- **On GCP**: Deployed within your project; compatible with **VPC Service Controls**.
- **On Azure**: Deployed within your VNet; integrated with **Azure Policy** and **Network Security Groups (NSGs)**.

## WisdomAI On-Premises

The On-Premises deployment model allows enterprises to run the entire WisdomAI analytics and agentic reasoning stack locally inside their own data center or private infrastructure. This model is explicitly designed for organizations with strict security, regulatory, data-residency, or air-gap requirements.

Under this model, **no customer data leaves your controlled environment** unless explicitly configured.

<Note>
  **Availability:** WisdomAI On-Premises deployment is exclusively available for strategic enterprise deals.
</Note>

### Core Stack Requirements & Architecture

The On-Premises version works inside a completely secure customer trust boundary through a localized, componentized layout:

1. **Access & Identity Layer**: Managed via a local customer load balancer using Bring Your Own Identity Providers (BYO IdP like Okta or Entra ID) to enforce enterprise SSO and RBAC completely locally.
2. **Kubernetes-Based Compute Layer**: Runs entirely on customer infrastructure to power:
   - Core Engine (orchestrating reasoning, context application & tools execution)
   - Context Engine (business rules & enterprise context)
   - Metadata Extractor (Ingests schema, table, and semantic metadata)
   - Chunker/Indexer (Processes documents and unstructured knowledge)
   - Agentic Tools (Text-to-SQL, RAG, Python / advanced analytics)
3. **Bundled On-Prem Storage Layer**: Includes a built-in OpenSearch Index & Vector DB (for keyword indexes, text indexes, and vector embeddings), alongside a Relational Database (Postgres) handling application metadata, audit logs, and context models.
4. **Bring Your Own LLM (BYO-LLM)**: Supports on-prem LLMs, private cloud LLM endpoints, or restricted Azure OpenAI/OpenAI via private connectivity. There is no hard dependency on any single model provider. You retain control over model selection, network access, and data exposure policies.

## Data flow (end-to-end)

Each request moves through the on-prem stack in the following sequence, with every step executing inside the customer environment.

1. The user request enters via the on-prem load balancer.
2. The Core Engine invokes the Context Engine.
3. Context is assembled from structured data, documents, and enterprise knowledge.
4. Agentic tools execute locally.
5. Results are returned to the user.
6. All logs and audit trails are stored on-prem.

### Operations & Upgrades

While infrastructure lifecycle monitoring and hardware patching remain under customer governance, WisdomAI supplies automatic upgrades over-the-air via the internet (cadence to be confirmed during onboarding). The customer retains the final say on precisely when updates are applied, along with full control over maintenance windows and rollback procedures.

## FAQs

The following questions cover common concerns about data handling in on-prem deployments.

<AccordionGroup>
  <Accordion title="Is the data encrypted in transit?">
    Yes. WisdomAI uses AES-256 and TLS 1.2\+.
  </Accordion>

  <Accordion title="Is there any data stored outside the customer environment?">
    No. For on-prem deployments, nothing is stored outside of the customer environment. The WisdomAI Customer Success team works jointly with the customer application admin to help set up the WisdomAI SDK and the embeddings database (for RAG) metadata.
  </Accordion>

  <Accordion title="How long is personal data stored?">
    WisdomAI does not store any personal data. The WisdomAI Platform connects to the customer's data warehouse via native and third-party integrations, and uses functionality provided by OpenAI and Anthropic to convert natural language into database queries and generate business intelligence from the data returned. Zero Data Retention (ZDR) agreements are in place with OpenAI and Anthropic. The customer can also choose to provide their own API key and host the WisdomAI Platform as a private SaaS instance within their environment.
  </Accordion>
</AccordionGroup>

## Comparison Summary

| Feature | WisdomAI Hosted (SaaS) | Customer-Hosted (Cloud-Prem) | WisdomAI On-Premises |
| :-- | :-- | :-- | :-- |
| **Infrastructure Owner** | WisdomAI | Customer (AWS, GCP, or Azure) | Customer (Bare-metal or private infra) |
| **Maintenance & Patching** | WisdomAI (Automated) | WisdomAI (Remote Managed Service) | Customer Controls Execution / Over-the-air Upgrades |
| **Data Residency** | WisdomAI Tenant | Customer Tenant | Customer Local Infrastructure |
| **Setup Complexity** | Low | Medium | High |
| **Infrastructure Cost** | Included in license | Paid via customer cloud account | Covered entirely by customer budgets |
| **LLM Key** | Included (with ZDR) | Included or Customer Key | Bring Your Own LLM (BYO-LLM) Required |

<Warning>
  Except for the **On-Premises** variant (where updates are pushed over-the-air but deployment timings are client-controlled), WisdomAI does not support customer-manual patching or architectural alterations. If your cloud environment has significant restrictions on third-party managed services, we recommend the **WisdomAI Hosted** option.
</Warning>
