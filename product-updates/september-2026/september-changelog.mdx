  ### ⚡ Wisdom Smart Cache

  Apps and dashboards no longer have to query your warehouse on every load. Wisdom Smart Cache serves them from Wisdom-managed snapshots of your tables, rebuilt on a schedule you control. Any query the cache can't serve runs against the warehouse, so caching changes how fast users get answers, never the answers themselves. Row-level security and column masking still apply at query time. For full details, see [Cache tables for faster apps and dashboards](/setting-up-wisdom-ai/cache-tables) and the [Smart Cache screen](/setting-up-wisdom-ai/smart-cache) pages.

  **⚙️ How it works:**

  - **Register tables for caching:** In **Domains → Data Sources**, register every cacheable table in a database, or a single table from its **...** menu. Choose a rebuild interval (hourly, 3, 6, 12, or 24 hours), add sort columns, or select **Build now**
  - **Smart Cache screen:** Open `/caching` to see the share of queries served from cache, the speedup, total data cached, and caches that need attention. **Candidates** ranks every app and dashboard by the warehouse time caching could win back
  - **Optimize:** Select **Optimize** on a candidate and WisdomAI registers the table caches the app's widgets are missing. Where a table is too large to cache, it creates cached views shaped to those widgets. Your app is never edited
  - **Activity tab:** See every cached table and view with its status, freshness, size, and queries served. Configure it, review its builds and usage, trigger **Build now**, or **Stop caching**
  - **Cached data on dashboards:** When a tile is served from the cache, the header shows **Data as of** the oldest data on the artifact. See [Cached data on dashboards and apps](/dashboards/cached-data)

  <Accordion title="FAQs">
    <AccordionGroup>
      <Accordion title="Does a table rebuild every time its interval elapses?">
        A table rebuilds when its interval has elapsed and its source data changed. If the warehouse reports no change, the existing snapshot is kept at no warehouse cost. **Build now** always forces a rebuild.
      </Accordion>

      <Accordion title="Can I turn caching off?">
        Yes. Go to **Domains → Advanced settings → Performance** and turn off **Materialized table cache**. Registrations are kept, and queries simply stop reading from the cache.
      </Accordion>

      <Accordion title="Does refreshing a dashboard rebuild the cache?">
        No. **Refresh Data** re-runs every widget query. Cached tables read the latest snapshot and everything else hits the warehouse. Rebuilds are controlled from Domains or with **Build now**.
      </Accordion>
    </AccordionGroup>
  </Accordion>

  <Note>
    Wisdom Smart Cache is in beta and is enabled per account. The Smart Cache screen is available to superusers.
  </Note>

  ### 🪞 Object Mirroring

  Share domains and dashboards across customer organizations. Your team maintains the originals, and each customer uses a live, read-only mirror in their own organization. Each customer gets their own WisdomAI organization, so one customer's users stay isolated from your other customers. For the concepts, see [Object mirroring](/access-management/object-mirroring).

  **⚙️ How it works:**

  1. Create the customer's organization and add its users
  2. Mirror the domain and the dashboard the customer needs
  3. Test access as a customer user
  4. Manage content and access after setup

  For the interface steps, see [Set up object mirroring](/access-management/set-up-object-mirroring). To do the same with the GraphQL API, see [Set up tenant organizations and mirrors with the API](/integrations/user-management/mirror-with-the-api).

  ### 🧩 Live Apps guides

  A new Live Apps section explains how to turn a plain-language prompt into an interactive data app built on the same governed foundation as your dashboards. Row-level and column-level security, domain permissions, and metric definitions apply to the app with no extra setup. For details, see the [Live Apps overview](/live-apps/overview).

  **⚙️ How it works:**

  - **Create an app:** Describe the view your team needs, refine it with chat and annotations, and migrate an existing dashboard. See [Create a Live App](/live-apps/create-live-app)
  - **See the data behind it:** Inspect any widget, open the **Sources** and **Code** views, and control how fresh the data is. See [Data Behind a Live App](/live-apps/data-and-trust)
  - **Share it:** Give teammates access with the same control model you use for dashboards, and export an offline copy. See [Share a Live App and Manage Access](/live-apps/share-and-access)

  ### 🔌 MCP Server guides

  The WisdomAI MCP Server guide is now split into step-by-step pages, so you can connect your AI client and then ask questions, give feedback, and manage context from it. Setup guidance for the MCP URL, authentication, and prerequisites is clearer, and the pages for deprecated MCP tools are removed. For setup, see [WisdomAI MCP Server](/integrations/mcp-server).

  **⚙️ How it works:**

  - **Ask a question:** Start a conversation, check for the result, respond if WisdomAI needs clarification, and continue the conversation. See [Ask a question via MCP](/integrations/mcp-server/ask-a-question)
  - **Give feedback:** Rate an answer or ask a domain admin for help. See [Give feedback via MCP](/integrations/mcp-server/give-feedback)
  - **Manage context:** Create and edit a draft, publish it, and reindex the domain. See [Manage context via MCP](/integrations/mcp-server/manage-context)

  ### 📥 Import an Apache Ossie model

  Apache Ossie is an open, vendor-neutral YAML format for describing datasets, relationships, metrics, and AI context. You can import an Ossie semantic model into a WisdomAI domain to reuse definitions your data team already governs.

  **⚙️ How it works:**

  1. Get an Ossie file and check the prerequisites
  2. Import the model into a domain
  3. Review what was imported
  4. To pick up upstream changes, re-import the file

  For the full steps and limitations, see [Import an Apache Ossie model](/setting-up-wisdom-ai/manage-domains/import-apache-ossie-model).
