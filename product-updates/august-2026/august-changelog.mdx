  ### 📚 Context Libraries

  Context Libraries let you share Knowledge across Domains without duplicating it. Until now, business context such as metric definitions or business rules lived inside the specific Domain where it was created, so teams working in a different Domain couldn't see or reuse it, and shared definitions had to be rebuilt (and kept in sync) in every Domain that needed them. A Library holds context outside any single Domain, so you define it once and reuse it everywhere it applies, while still controlling which Domains can access it.

  **⚙️ How it works:**

  1. From the **Domains** page, click the **Context Libraries** icon to view every Library's Name, Description, Linked Domains, and Last Updated date
  2. From a Domain's **Knowledge** tab, select an item and click **Move to Library** to move it into a new or existing Library
  3. From a Domain's **Context** tab, go to **Knowledge → Libraries** and select which Libraries to link
  4. Once linked, Knowledge in the Library is available for query interpretation in that Domain, alongside the Domain's own Knowledge

  <Frame>
    ![Context Libraries](/images/new-link-domain2.png)
  </Frame>

  <Accordion title="FAQs">
    <AccordionGroup>
      <Accordion title="Does moving Knowledge to a Library remove it from the original Domain?">
        It moves into the Library rather than staying as a Domain-local item. To keep using it in that Domain, link the Domain to the Library.
      </Accordion>

      <Accordion title="Can a Library be linked to more than one Domain?">
        Yes. Linking is a separate, explicit step per Domain, so you control exactly which Domains can access a given Library's Knowledge.
      </Accordion>
    </AccordionGroup>
  </Accordion>

  ### 🔀 Domain Groups & Auto Domain Selection

  Some questions legitimately span more than one Domain, "Is churn related to a drop in product engagement?" needs a retention Domain and a product-usage Domain at once. Two new features answer cross-domain questions without abandoning Domain isolation: **Auto Domain Selection**, which reads each question and routes it to the most relevant Domain or Group at runtime, and **Domain Groups**, which let an admin bundle two or more Domains that are known to be related ahead of time, complete with their own shared context and cross-domain reviewed query library.

  **⚙️ How it works:**

  1. Admins enable Auto mode from **Settings → Cross-Domain Settings → Auto Domain Selection**, optionally scoping it with a Domain Greenlist in workspaces with more than 10 Domains
  2. In chat, select **Auto** (sparkles icon) from the domain selector to have WisdomAI route each question automatically
  3. Admins create a Domain Group from **Settings → Cross-Domain Settings → Domain Groups → Add Group**, naming it and selecting two or more Domains
  4. Select a Group (marked with a **Group** chip) from the domain selector to reason across every Domain in it, or add shared context and reviewed queries at the group level via **Manage Context**

  <Frame>
    ![Domain group creation screen showing domain selection](/images/domain-froups-create.png)
  </Frame>

  <Accordion title="FAQs">
    <AccordionGroup>
      <Accordion title="Do I have to choose between Auto Domain Selection and Domain Groups?">
        No, they compose. When Auto mode is on, WisdomAI can route to a Domain Group as well as an individual Domain, if a relevant group already exists, Auto mode uses it instead of reasoning across the full Domain set.
      </Accordion>

      <Accordion title="When should I create a Domain Group instead of relying on Auto?">
        When an admin already knows, from experience, that specific Domains are routinely asked about together. Declaring that relationship as a group constrains WisdomAI to a small, known-relevant set of Domains with its own shared context, rather than re-deriving the relationship at runtime for every question.
      </Accordion>
    </AccordionGroup>
  </Accordion>

  </Note>

  ### 🧠 Knowledge signals from chat

  Every conversation where a user corrects an answer, clarifies a metric, or states a business rule is a potential source of domain knowledge, and until now, that signal was easy to lose after the chat ended. Knowledge Signals from Chat closes that loop across three surfaces: reviewing a full conversation on demand, seeing what context an answer actually used, and, new this month, catching the moment knowledge changes hands while the conversation is still happening, with no button press required.

  **⚙️ How it works:**

  - **On-demand suggestions:** Click the brain icon (**Knowledge Suggestions**) in any conversation's chat controls bar to analyze the full conversation and surface suggested knowledge entries. **Accept**, **Decline**, or edit each one inline before it's added to your Domain Knowledge base
  - **Context used:** Click the **ⓘ** icon on any answer to see what context was retrieved and applied, useful for catching a stale or incorrect knowledge entry behind a wrong answer
  - **Automatic mid-chat capture (new):** WisdomAI now watches conversations for an explicit "remember this" instruction or a correction to existing knowledge, and proposes an add or update inline, below the response, using the same Accept / Decline / Edit review, no button press required

  <Accordion title="FAQs">
    <AccordionGroup>
      <Accordion title="Does accepting a suggestion take effect immediately?">
        Yes. Once accepted, from any surface, the entry is written to the domain knowledge base and available for retrieval on the next query.
      </Accordion>

      <Accordion title="How does automatic mid-chat capture differ from the brain icon?">
        Mid-chat capture looks for two narrower, higher-confidence signals, an explicit "remember this" instruction, or a clear correction or clarification of existing knowledge, and proposes automatically the moment either is detected. The brain icon remains the broader, on-demand option: it analyzes an entire conversation regardless of whether either signal was present. They're complementary, not a replacement of one for the other.
      </Accordion>

      <Accordion title="What if I accept something that's wrong?">
        Navigate to the Domain Knowledge tab. The confirmation notification after acceptance includes a direct link. You can edit or delete the entry there.
      </Accordion>
    </AccordionGroup>
  </Accordion>

  <Note>
    This feature is restricted to Domain Admins today, across all three surfaces. Expansion to explorers is planned.
  </Note>
