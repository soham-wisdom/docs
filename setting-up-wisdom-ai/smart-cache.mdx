title: "Smart cache screen"
---

Wisdom Smart Cache is in beta and is enabled per account. The Smart Cache screen is available to superusers.

The Smart Cache screen shows how much of your account's query time is served from cache, and where caching could help next. Open it at `/caching`.

## Overview tab

Four cards summarize the last 7 days:

- The share of app and dashboard queries served from cache.
- Cache latency against the warehouse, with the speedup when the cache serves.
- Total data cached.
- Caches that need attention.

Below the cards, **Candidates** ranks every app and dashboard by the warehouse time its queries spent, which is the time caching could win back. Each row shows query counts, bytes scanned, and latency.

## Optimize an app

Select **Optimize** on a candidate to start an optimization run for it. The optimizer reads the app's widgets and registers the table caches they're missing. Where a table is too large to cache, it creates cached views shaped to those widgets.

An optimization run handles one app at a time and opens as a conversation, so you can follow what it found and why.

WisdomAI doesn't edit your app. Widget queries stay exactly as written, and removing a cache or cached view changes nothing about the app.

## Activity tab

The **Activity** tab lists every cached table and view in the account, with kind, connection, status, freshness, size, and queries served over the last 7 days. Filters live in the URL, so you can share a filtered view as a link.

Select any item to:

- Configure it.
- View its builds and usage.
- See its read-only definition.
- Trigger **Build now**.
- Select **Stop caching**.

Cache builds run as jobs. To pause, resume, re-schedule, or cancel a build, use the **Jobs** page at `/jobs` (site admins and superusers).

## Cached views

The optimizer creates cached views and lists them on the Smart Cache screen. You can see their SQL but not edit it. To own and edit the SQL, create a derived table and cache it through the domain workflow instead.
