---
title: "Cache tables for faster apps and dashboards"
---

Register your tables for caching so apps and dashboards load from WisdomAI-managed snapshots instead of querying the warehouse.

When you register a table, WisdomAI builds a compressed snapshot on a schedule and serves queries from it. Queries the cache can't serve run against the warehouse. Caching changes how fast users get answers, never the answers themselves. Row-level security and column masking still apply at query time.

<Note>
  Wisdom Smart Cache is in beta and is enabled per account. Contact your WisdomAI representative to turn it on.
</Note>

## Register tables for caching

To register tables for caching:

1. Go to **Domains** and select a domain.
2. Open **Data Sources** and choose a database.
3. Register your tables:
   - To register every cacheable table, select the cache button next to **Add table**. Choose a rebuild interval, then select **Register**.
   - To register a single table, open the table's **...** menu and select **Register Cache**. Then set the options in the **Register Cache** dialog.

In the **Register Cache** dialog you can:

- Choose a rebuild interval: hourly, 3, 6, 12, or 24 hours.
- Add sort columns so filtered queries scan less of the snapshot.
- Select **Build now** to build the snapshot immediately.

After you register a table, its status chip shows the state of the cache. See [Cache status](#cache-status).

## Cache status

Registered tables show a status chip:

| Status | Meaning |
|---|---|
| **Cached** | The snapshot is serving queries. |
| **Stale** | The snapshot expired. Queries read from the warehouse until the next build. |
| **Registered** | The table is registered but not built yet. |
| **Not eligible** | The table is over the size budget. **Build now** retries it. |
| **Not cached** | The table is not cached. |
| **Unsupported** | The table can't be cached, for example uploaded files or connections that use per-user credentials. |

## How rebuilds work

A table rebuilds when its interval has elapsed and its source data changed. If the warehouse reports no change, WisdomAI keeps the existing snapshot at no warehouse cost. **Build now** forces a rebuild.

Cache rebuild cadence is separate from column-value crawl cadence. Column-value crawls default to every 7 days and you configure them per domain. Changing one setting doesn't change the other.

Cache builds run as jobs. Site admins and superusers can pause, resume, re-schedule, or cancel them from the **Jobs** page at `/jobs`.

## Turn caching off for a domain

To stop a domain from serving queries from the cache, turn off its table cache setting.

1. Go to **Domains** and select a domain.
2. Open **Advanced settings** > **Performance**.
3. Turn off **Materialized table cache**.

WisdomAI keeps your registrations, and queries stop reading from the cache.

## Security and limits

Caching never changes who can see your data, and some tables can't be cached.

- Row-level security and column masking always apply at query time. Caching never widens what a user can see.
- Data that depends on the querying user is never cached.
- WisdomAI skips very large tables and marks them **Not eligible**.
